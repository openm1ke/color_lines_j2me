# Color Lines J2ME

«Цветные линии» для CLDC 1.1 / MIDP 2.0: перемещай шары по свободным клеткам
и собирай линии из пяти и более шаров одного цвета. Есть сохранение партии, подсветка доступных клеток и пути, последовательное
удаление линий, подскок выбранного шара, Undo и статистика для разных правил.

## Сборка и запуск

Нужен **JDK 21**. Сборка и проверки работают на Java; системный Ant и старый JDK не требуются.
Из корня проекта:

```sh
./antw run        # собрать и открыть FreeJ2ME: 240×320, увеличение ×2
./antw package    # создать dist/lines.jar и dist/lines.jad
./antw test       # проверить сборку, игровые сценарии, настройки и аудио
./antw clean      # удалить build/ и dist/
./antw check-emulator  # сценарии в окнах FreeJ2ME (нужен графический сеанс)
```

Прямой вызов без shell-обёртки: `java tools/AntBootstrap.java run`.
Так же можно вызывать `package`, `test`, `clean` и `check-emulator`.
Именно этот Java-вызов используют конфигурации OpenIDEA.
Первый запуск скачивает Ant 1.10.15
и Eclipse Compiler 3.26.0 с Maven Central в `tools/build/`, проверяя SHA-256.
После загрузки сборка работает без сети. `JAVA_HOME`, если задан, должен
указывать на JDK. `./antw` — короткая shell-обёртка, которая выбирает Java
из `JAVA_HOME` либо `PATH` и передаёт аргументы Java-загрузчику.
Для прямого вызова из другой папки передай `--project-root /путь/к/проекту`
перед именем цели. J2ME API, FreeJ2ME и ProGuard уже включены в репозиторий.

Вся цепочка: Java-загрузчик → Ant → Eclipse Compiler → ProGuard → JAR/JAD.
Проверки дистрибутива и запуск эмуляторов написаны на Java; игровые тесты
компилирует JDK через Ant. Python в этой цепочке не используется.

Компилятор проверяет исходники как Java 1.3 и создаёт Java 1.1 bytecode против
CLDC/MIDP API. ProGuard выполняет CLDC preverification. JAD содержит профиль
MIDP-2.0 и актуальный размер JAR. Обычный современный `javac` не подходит для
этих параметров. Для системного Ant после загрузки инструментов:

```sh
ant -lib tools/build/ecj-3.26.0.jar package
```

Название, версия и MIDlet задаются в `local.properties`. Разрешение и масштаб:

```sh
./antw -Demulator.width=240 -Demulator.height=320 -Demulator.scale=3 run
```

Перед повторным запуском или очисткой закрой старое окно эмулятора: открытый
JAR на NTFS может мешать удалению `dist/`. Hot reload и отладка J2ME не настроены.

## Редактирование в OpenIDEA

Открой корень проекта. Конфигурации в `.openidea/run.toml`:

- **Lines — FreeJ2ME 240x320** — сборка и запуск;
- **Lines — Build JAR + JAD** — сборка;
- **Lines — Check** — проверки;
- **Lines — Clean** — очистка;
- **Lines — Emulator checks** — автоматический прогон в видимом FreeJ2ME.

Для автодополнения и переходов нужен Eclipse JDT Language Server (JDK 21+),
выбранный в настройках OpenIDEA. `.project` и `.classpath` задают `src/` и два
J2ME API JAR; эмулятор и ProGuard не входят в classpath приложения. Уровень
Java 8 в `.settings/` нужен современному серверу редактора; настоящая сборка
проверяет Java 1.3 и CLDC. После изменения метаданных переоткрой проект.

## Управление

- Стрелки — перемещение курсора, выбор пункта меню или значения настройки.
- Enter — START, выбор шара и клетки назначения, изменение настройки.
- После выбора шара стрелки показывают путь до клетки; перетаскивание указателя
  также позволяет посмотреть маршрут перед нажатием на цель.
- Q — левая софт-клавиша: Select / Undo / Save.
- W — правая софт-клавиша: Menu в игре, Back в настройках, Exit в главном меню.
- 2/4/6/8 (NumPad) — курсор, 5 — выбор; удержание направления повторяет движение
  после 320 мс, далее каждые 120 мс. FIRE не повторяется автоматически.
- NumPad 1 — Undo во время игры и после проигрыша.
- Мышь — выбор клеток, пунктов меню и экранных софт-клавиш.

Привязки можно изменить в Settings эмулятора. В FreeJ2ME Q означает левую
софт-клавишу; в исходнике также есть обработка буквенного кода `q` для выхода.

## Настройки и рекорды

В **SETTINGS** доступны 11 настроек; на экране 240×320 одновременно видны
девять. До остальных можно прокрутить список стрелками:

| Настройка | Значения |
| --- | --- |
| Board | 7×7, 9×9, 11×11 |
| Colors | 3–7 |
| New balls | 1–3 новых шара после хода без линии |
| Music | On / Off |
| Music volume | 0–100%, шаг 5% |
| Effects | On / Off |
| Effects volume | 0–100%, шаг 5% |
| Patterns | узоры на шарах On / Off |
| Difficulty | Relaxed, Normal, Classic или Custom |
| Vibration | On / Off; изначально выключена |
| King | Red, Emerald за 3 достижения, Sapphire за 6 |

Музыка и эффекты имеют независимые выключатели и уровни громкости.
Изменения звука слышны сразу. **Save** сохраняет настройки и возвращает в меню;
**Back** отменяет изменения, включая предпрослушанную громкость. При ошибке
сохранения экран остаётся открытым с предупреждением.

Правила применяются к **NEW GAME**. **RESUME** продолжает старую партию с
прежними параметрами. Стартовый режим: 9×9, 5 цветов, 3 новых шара. Для
спокойной игры выбери **Relaxed**: 9×9, 4 цвета, 1 новый шар. **Normal** —
9×9, 5 цветов, 2 шара; **Classic** — 9×9, 7 цветов, 3 шара. Ручные изменения
показываются как **Custom**. Линия требует минимум 5 шаров при любом размере поля.
**Patterns** добавляет каждому цвету свой знак: точку, полоску, крестик, кольцо
или квадрат. Узоры видны и на выбранном шаре, и в предпросмотре; правил они не меняют. Занятая игроком клетка предпросмотра не
уничтожает запланированный шар: он переносится в другую свободную клетку.

В **STATISTICS** сохраняется лучший результат отдельно для каждой из 45
комбинаций правил, с указанием размера поля, числа цветов и новых шаров.
Дополнительно для каждого режима видны **G** — начатые партии, **M** — общее
число завершённых ходов и **L** — самая длинная непрерывная собранная линия.
Пересечение двух линий даёт очки за все уникальные шары, но не завышает длину линии.
Счётчики начатых партий и сыгранных ходов не уменьшаются при Undo; повторный
ход считается ещё одной попыткой. Продолжение сохранения не считается новой партией.
Новые счётчики ведутся с этой версии; прежние рекорды сохраняются.
Рекорд обновляется при начислении очков; Undo его не стирает. Данные
хранятся в RMS данного MIDlet на устройстве, без облачной синхронизации.
Обновление формата настроек сохраняет старые рекорды. В FreeJ2ME записи
находятся в `rms/`; удаление этого каталога сбросит настройки и результаты.

Каждая новая партия получает новый seed; Undo восстанавливает случайную
последовательность. История ограничена 128 снимками — до 127 отмен.

## Продолжение игры и помощь

После нового старта и каждого завершённого хода игра автоматически сохраняет
поле, правила партии, счёт, число ходов, рекорд длины линии, следующие шары
и RNG в отдельный RMS-слот с контрольной суммой. При следующем запуске
появляется **RESUME**. Если приложение прервано посреди перемещения или удаления
линии, восстанавливается последний завершённый ход, без частично исчезнувших шаров.
Пауза и выход также сохраняют стабильный снимок. История Undo после перезапуска
начинается с восстановленного хода; более старые снимки не записываются на диск.

На полном поле появляется GAME OVER и сохранение завершённой партии удаляется.
Undo после проигрыша возвращает игру и снова создаёт слот продолжения.
**NEW GAME** просит подтверждение замены незаконченной партии; **Cancel** её
сохраняет, а **New** начинает новую с выбранными настройками.

В меню **HELP** есть прокручиваемая справка с правилами и управлением. Доступные
клетки подсвечиваются при выборе шара, пунктир показывает путь до курсора.
Невозможный ход даёт короткое покачивание и сохраняет выбор; нажатие на другой
шар переключает выбор. Шары в линии исчезают последовательно, затем появляется
`+очки`; видимый счёт плавно догоняет точное игровое значение.


## Музыка и эффекты

**Minigame soundtrack — Kirard**, исходный MIDI (~50 КБ, 4:10):
[страница автора на OpenGameArt](https://opengameart.org/content/minigame-soundtrack).
Лицензия [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).
Файл не изменён; сведения включены в `res/music/LICENSE.txt` и ABOUT.
Музыка изначально выключена, громкость 35%. MIDI зациклен; его тембр зависит
от синтезатора телефона или эмулятора.

**Pop sounds — EZduzziteh**, три варианта pop1/pop2/pop3:
[источник](https://opengameart.org/content/pop-sounds-0),
[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).
Оригиналы stereo 44.1 kHz преобразованы в mono PCM WAV 16 kHz/16 bit:
2–4 КБ на эффект, 0,06–0,13 секунды. Сведения о преобразовании включены в
`res/sfx/LICENSE.txt` и ABOUT. Эффекты изначально включены, громкость 70%.
Один короткий pop запускается при начале удаления линии; варианты чередуются,
не меняя игровой RNG и не накладываясь в громкий залп.

Медиа загружается в отдельных потоках, останавливается на паузе и освобождается
при выходе. Ноль отключает соответствующий звук. Недоступное аудио не прерывает
игру; настройки показывают предупреждение.

## Проверки и устройство проекта

`./antw test` проверяет метаданные и ресурсы JAR/JAD, версию байткода, CLDC
StackMap и отсутствие встроенных классов J2ME API. Игровые проверки работают
с настоящим кодом и MIDP-реализацией FreeJ2ME:

- все 45 режимов, границы поля, появление шаров и удаление линий;
- первый ход и Undo, перенос занятых предпросмотров, восстановление RNG;
- ограничение истории и освобождение снимков;
- очередь ввода, одновременные события, паузу, возобновление и Exit;
- RMS: перезагрузку, повреждённые данные и миграцию формата;
- независимую громкость, mute/unmute, отключение эффектов и отказ аудио;
- отдельные действия Save/Back для клавиш и мыши;
- сохранение/восстановление обычного хода и удаления линии, контрольную сумму,
  очистку сохранения при проигрыше и возврат сохранения через Undo;
- подсветку доступных клеток и маршрутов, невозможные ходы, узоры, пресеты,
  подтверждение новой игры и читаемость справки;
- статистику партий, ходов и длины непрерывной линии;
- изменение кадров bounce без изменения игрового состояния.

Тесты используют отдельное RMS-хранилище `lines-automated-check`, не затрагивая
пользовательские рекорды; новые функции проверяются в `lines-feature-check`.
Снимки экранов записываются в `build/previews/`.

`./antw check-emulator` сначала выполняет эти тесты, затем запускает настоящий
FreeJ2ME с готовым JAR и автоматическими действиями клавиш/указателя. Проверяются
реальный ход, маршрут, удаление линии, очки, перезапуск MIDlet с восстановлением,
узоры, пресеты, подтверждение новой игры, справка, статистика и все три размера поля.
Экраны дополнительно проверяются отдельными запусками при 240×320, 176×208 и 320×240.
Данные и конфиги этих запусков изолированы в `build/emulator-check/runtime-*`,
скриншоты — в `build/emulator-check/`. Окна тестов закрываются после проверки.
Входа в аккаунты и доступа к пользовательским сохранениям этот сценарий не требует.

У включённого FreeJ2ME есть ограничение: смена разрешения на лету не пересоздаёт
буфер GameCanvas. Для другого размера экрана перезапусти MIDlet/эмулятор. Проверки
на разных разрешениях поэтому используют отдельные запуски, как на фиксированных
экранах телефонов. Они не заменяют полное прохождение на настоящем устройстве.

Исходники находятся в `src/lines/`, ресурсы — в `res/`, тесты — в `tests/`.
Ввод, Undo, правила, анимация и отрисовка обрабатываются игровым потоком;
колбэки передают запросы через очередь на 32 события. Пауза очищает очередь,
а Exit может остановить игру независимо от анимации и заполнения очереди.

`build/`, `dist/`, `tools/build/`, `rms/`, `config/`, `freej2me_system/` и
личное состояние IDE исключены из Git. Общие конфигурации редактора и запуска,
исходники, тесты, аудиоресурсы и их лицензии включены в репозиторий.

Оригинальная Color Lines разработана Олегом Дёминым, Геннадием Денисовым и
Игорем Ивкиным и издана Gamos в 1992 году. J2ME-версия: openm1ke.

WAV-эффекты используют простой 44-байтовый заголовок PCM без LIST/INFO:
WAV-декодер включённой версии FreeJ2ME не умеет пропускать эти метаданные.
При загрузке поток буферизуется для поддержки mark/reset. Тесты декодируют
все эффекты непосредственно из JAR через FreeJ2ME и проверяют длительность
и ненулевой PCM-сигнал, не требуя аудиоустройства.

## Шарик-король и пьедестал

Справа от поля стоит пиксельный шарик-король с короной, плащом и скипетром.
Новая партия начинается с подставки высотой 2 пикселя (4 на широком экране).
Без очков она не растёт. После удаления шаров пьедестал плавно растёт вместе со счётом,
а король коротко подпрыгивает. Первые 5 очков дают около 1% доступного роста,
500 очков — половину, 1000 — около двух третей. Рост постепенно замедляется
и ограничен высотой поля, поэтому корона остаётся на экране.
При новой партии пьедестал сбрасывается, Undo и Resume восстанавливают высоту
по текущему счёту. Персонаж не меняет правила, случайную последовательность
или рекорды. Для него выделена отдельная область справа; клетки и подсказки
автоматически вписываются в оставшееся место.

Исходный персонаж разобран в карту 70×66 в `src/lines/KingPixels.java`:
все пиксели заданы символами исходной восьмицветной палитры. PNG
`res/images/king.png` сохранён как эталон для попиксельной проверки.
При извлечении из снимка ровные блоки 3×3 сведены к одному пикселю.
Внешний чёрный фон отделён от внутренних контуров со всех краёв.

При отрисовке размер вычисляется по доступной ширине. Уменьшение выбирает
доминирующий исходный цвет по площади покрытия, без размытия и новых цветов.
Для размеров меньше оригинала глаза строятся отдельно на общей пиксельной
сетке: одинаковые белки, раздельные зрачки, красный нос и белый зуб.
Тонкие перекладины скипетра, крестик короны и красные камни также
привязываются к целым пикселям, чтобы не исчезать при уменьшении.
Это адаптация деталей под малый размер, а не обычное уменьшение картинки.
Ширина спрайта — 28/35/56 пикселей, зазор до поля — 10/12/16 пикселей
для узких/обычных/широких экранов соответственно. При очень малом размере
все исходные детали физически не помещаются; сохранены силуэт и черты лица.
Колонна использует исходную двухстрочную текстуру, сохраняя обе фазы узора.
Растры кэшируются при расчёте размера экрана, а не создаются в каждом кадре.

Автотесты проверяют точное совпадение исходных пикселей, размеры 1–140,
различимость обоих глаз на вертикальном экране, рост/сброс пьедестала,
восстановление высоты и отсутствие влияния на игровое состояние.
FreeJ2ME проверяет три размера экрана и сохраняет снимки.

## Прогресс и новые режимы

Король радуется удалению линии (сильнее при 7+ шарах), празднует новый рекорд
и тревожится, когда свободно не больше 1/8 поля. Золотая отметка PB на колонне
показывает рекорд до начала партии. Эта цель остаётся прежней до конца партии,
включая Resume. Превышение цели поздравляет один раз; Undo не повторяет награду.

После проигрыша отдельный экран показывает очки, ходы, длиннейшую линию,
правила, прежний рекорд и разницу до победы над ним. Левая софт-клавиша Retry
и FIRE запускают ещё одну партию с теми же правилами. Правая открывает меню.
Клавиша 1 позволяет отменить проигрыш, пока история хода есть в памяти.

В меню DAILY — задача дня без интернета: дата определяется по UTC, правила
всегда 9×9 / 5 цветов / +2. Для одной даты начальное поле и последовательность
шаров совпадают; одинаковые действия дают одинаковые результаты. Retry
повторяет ту же дату, даже после полуночи. При выборе новой задачи дня
текущая партия заменяется только после подтверждения. Сохраняются режим,
дата и состояние генератора; обычные рекорды и счётчики партий не меняются.
Локальная история хранит лучшие результаты за 14 последних дат с очками.
У всех игроков доступны обычные подсказки и Undo; проверки даты через сеть нет.

В ACHIEVEMENTS — 10 постоянных достижений: первая линия, линия 7+,
несколько линий за ход, 100/500 очков, 100 ходов, выход из почти полного поля
(не больше 5 свободных клеток на предыдущем завершённом ходу), завершение
задачи дня с очками, превышение прежнего ненулевого рекорда, линии на всех
трёх размерах поля. За 3/6 достижений открываются Emerald/Sapphire.
В SETTINGS можно выбрать доступный облик; правила и RNG от него не меняются.
Достижения и рекорды остаются после Undo и повторно не начисляются.

Вибрация выключена по умолчанию. При включении запрос к MIDP Display.vibrate
составляет 50 мс за линию или 180 мс за новый рекорд. Поддержка физической
вибрации зависит от телефона/эмулятора. В паузе и после выхода запросов нет.
Save сохраняет вибрацию и облик, Back отменяет их вместе с остальными настройками.

Прогресс и задача дня хранятся в отдельном RMS `*-progress`; прежние рекорды
не переписываются. SessionStore читает старую версию сохранения и записывает
новую с датой, исходным рекордом и состоянием партии. Дополнительный набор
`ProgressionCheck` проверяет миграцию, повторяемость дня, изоляцию рекордов,
достижения, награды, ввод и запросы вибрации. Эмуляторные проверки проходят
все новые экраны и управление на 176×208, 240×320 и 320×240.
